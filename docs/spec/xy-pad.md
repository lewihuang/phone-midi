# X/Y Pad（二维控制面）— 方案与步骤分解

> 状态：**已实现**（2026-09-26 需求拷问定稿 → 同日实现；Bridge 侧 21 项 + 手机端 19 项检查）。
> 关联：[CONTEXT.md](../../CONTEXT.md)（X/Y Pad / Position / Position Marker / Landing / Drag / Recentre）·
> [ADR 0004](../adr/0004-midi-note-triggers.md)（"离散事件绕开映射引擎"的先例）·
> [roadmap](../roadmap.md)（"XY Pad 触屏"候选）
>
> 目标：**把手机屏幕变成 DAW 里粒子/颗粒合成器那个 X/Y Pad** —— 一个触点同时决定两个连续参数
> （X 轴一个 CC、Y 轴一个 CC），**位置即值、松手保持**，且**跟手**。

---

## 1. 定位

| | 说明 |
|---|---|
| **是什么** | MIDI Deck 的第三个功能模块（与 Digital Fader、Shortcut Pad 并列） |
| **谁在用** | 坐在 DAW 边上的人，正在调粒子合成器的音色云位置 |
| **和谁搭配** | 插件自己的 MIDI Learn；或 Nuendo 的 MIDI Remote（两者都只是"学两个 CC"） |
| **入口** | 首页模块列表第三张卡片；路由 `/xy.html` |

**为什么不是"推子的一个模式"**：模式 A/B/C 读传感器、要校准，X/Y 读触屏、不校准；
而且手机同一时刻只能显示一页 —— 它是模块，不是模式（与 Shortcut Pad 同类）。

---

## 2. 已定决策

| # | 决策 | 依据 |
|---|------|------|
| **1** | **绝对语义 + 松手保持**：位置就是值，手指离开后 Position 不变 | 粒子合成的 XY 面就是"一个位置"，要停在那儿听；回中等于每次松手都把音色归零 |
| **2** | **Position Marker 必做**，松手后仍留在原处 | 决策 1 的直接前提：不显示当前位置，用户就不知道参数停在哪 |
| **3** | **Landing 用一小段补间（≈40 ms）抹掉跳变；Drag 零平滑、零插帧、零延迟** | 直跳在粒子位置/密度上常有可听的不连续；但按着移动这条路径必须保持"跟手优先"（Mode B 删掉整条滤波链的教训：**滤波不是在这里加的**）。落点之后手指怎么动就怎么发 |
| **4** | **不走映射引擎**：手机发 `{kind:'xy', x, y}`，Bridge 直接变成两条 `send_cc` | 引擎是单轴的，还带 curve / dead-zone / smoothing 一整套；X/Y 两轴都是**线性、无死区、无平滑**，曲线交给插件自己的响应曲线。做法沿用 ADR 0004 的先例 |
| **5** | **纯 7-bit CC**（每轴 0–127），不做 14-bit、不留开关 | 插件 MIDI Learn 的普遍现实就是 7-bit；14-bit 要占两个 CC 号且多数插件只学高位，等于白发。项目里只有弯音是真 14-bit（那是消息自带 14 位） |
| **6** | **两个 CC 号 + 通道在手机页面上可改**，改完立刻生效并**落盘**，重启 Bridge 还在 | 在琴边上改 CC 是最常变的一件事，而"插件 Learn 到了哪个号"只能看插件 —— 让你为此跑去 PC 点菜单是反着来的。**顺带修掉推子"重启就忘 CC/Ch"的旧毛病**（`set_target` 一直是纯内存） |
| **7** | **端口与推子共用**，不需要独立 MIDI 端口 | 面板当初要独立端口是因为它的**音符**会被 `All MIDI Inputs` 里的音源轨（OMNI）吃到（D14）；而 X/Y 的 CC **本来就是要喂乐器轨**的 |
| **8** | **第一根手指独占**，第二根落下不夺权 | 绝对语义下"误触"的代价是参数被瞬移并停在那儿；夺权会让两根手指打架的行为无法解释 |
| **9** | **正方形控制面**，比屏幕略小一圈（四边都不顶屏幕边缘） | 用户要求；两轴等比例，不会因为屏幕 390×844 让 X 比 Y "敏感"。插件里的 XY 面本来就长这样 |
| **10** | **回中按钮必做** | 误触之后的逃生口：不用猜原来的值 |
| **11** | **面内显示：Marker + 十字准线 + 两个数值**（`X 64 · Y 96`）；不做网格、不做轨迹 | 十字线是 XY Pad 的通用语言；数值是"发出去多少"的唯一即时证据（手机端没有震动可用，看不见就等于不确定）。358 px 里加网格信息量太低；轨迹会糊成一片还盖住 Marker |
| **12** | **Y 轴向上 = 值变大；X 向右 = 值变大**；**不做轴反转开关** | 与插件 XY 面一致；万一某个插件是反的，在插件里调，别在手机上多一个开关 |
| **13** | **Marker 跟着那 40 ms 补间一起走** | 屏幕上看到的 = 实际发出去的。否则会出现"画面到了、值还没到"的错觉 |
| **14** | **未触碰前是"未定"状态**：虚线环停在中心、数值显示 `X — · Y —`、一句"点一下控制面开始"；**一个值都不发**。首次落点才从"未定"变成真实 Position（补间从中心出发） | 打开页面就发中心值 = 静默改掉插件里音色的位置。状态必须诚实：没发过就是没发过 |
| **15** | **冻结开关**（默认不冻结）：冻结时 Marker 仍可拖、数值仍更新，但**一个 CC 都不发**；解冻时**只发一次当前值** | "先把云的位置摆好，再开始听/开始录"是真实用法；解冻那一次正好把插件拉到位 |
| **16** | **断连时**：控制面灰底、拖动不发送、数值行显示「未连接」 | 沿用既有准则：**"按了没反应"比"明显不能按"更糟**（面板页同款处理） |
| **17** | **不需要任何 watchdog** | 绝对 + 保持语义：值就该留在那儿。既不像弯音需要死手归中，也不像面板触发需要补 Note Off |
| **18** | **模块名 = X/Y Pad**，卡片不带副标题；同时把另两个模块显示名改成 **Digital Fader** 与 **Shortcut Pad** | 用户要求；三个模块名统一成英文，且 `Shortcut Pad` 正是文档里的既有术语，不需要再造"模块名 ↔ 术语"对照表 |
| **19** | **PC 端程序名不动**（仍是 `MIDI Deck.exe` / 「MIDI Deck」） | 桌面快捷方式指着这个文件名；要改得连打包脚本、`.spec`、日志路径与快捷方式一起动。手机端模块名与 PC 端程序名是两件事 |

## 3. 行为规格

### 3.1 控制面

- **正方形**：边长 = `min(可用宽, 可用高)`，居中；四个边都不贴屏幕边缘（握持时不容易蹭到）。
- **触摸区域 = 正方形内部**；位置线性映射到两轴：左边缘 = 0、右边缘 = 127、下边缘 = 0、上边缘 = 127。
- **不设死区、不设端点吸附**：边缘就是 0/127（用户要的是完整行程）。
- 页面整体**不滚动、不缩放、不长按菜单**（`touch-action: none` + 禁选中），与面板页同一套处理。

### 3.2 手指与状态

| 事件 | 行为 |
|------|------|
| 未触碰 → 第一次落下 | **Landing**：Position 从"未定中心"补间到触点（≈40 ms），此后 Marker 实心、数值为真值 |
| 按着移动 | **Drag**：Position 直接跟手；**不插帧、不平滑**；值变一档就发 |
| 抬起 | Position **保持**（Marker 留在原处）；**不发任何"归零/归中"** |
| 第二根手指落下 | **忽略**（第一根抬起后它才有资格）；不夺权、不叠加 |
| 点「回中」 | Position 移到正方形正中，**走与 Landing 同一条补间**（它和 Landing 是同一类移动：把 Position 挪到别处），结束时把两个中心值发出去 |
| 点「冻结」 | 停止发送；Marker 与数值仍随手指更新（它表示"解冻后要去的位置"） |
| 解冻 | 从当前发出值补间到 Marker 位置（同一条 40 ms），结束时把两个值发出去 |

### 3.3 发送

- 每个轴 7-bit（0–127，四舍五入）。
- **只有该轴的值真的变了才发那一条**（两轴独立判断；只动 X 就只发 X）。
- 两次发送之间**最少 4 ms**（与推子同一条下限，防止病态事件率灌满链路）。
- 通道：与推子同一个 MIDI 端口，通道号在页面上可改（默认与推子一致的 Ch 1）。

## 4. 协议与数据

**手机 → Bridge**（沿用现有 `{...}` 形状；`kind` 区分语义）

```json
{ "kind": "xy", "x": 64, "y": 96, "cc_x": 20, "cc_y": 21, "channel": 0 }
```

- `x` / `y` 是 **0–127 的整数**（手机直接给 7-bit，不做浮点归一化 —— 这一层没有曲线、没有量程，浮点只会多一次四舍五入的争议）。
- `cc_x` / `cc_y` / `channel` **每条都带**：Bridge 侧以"最近一次收到的配置"为准，这样多设备/重连都不会用到过期配置。
- Bridge 收到后：**两条 `send_cc`**，不经过映射引擎（决策 4）。

**配置落盘**：`%APPDATA%\phone-midi-bridge\xy.json`

```json
{ "cc_x": 20, "cc_y": 21, "channel": 0 }
```

读取时清洗：非整数、越界（CC 0–127、通道 0–15）、两轴撞号（**允许但不用管**，那是用户自己的事）→ 非法值退回默认。
默认值：`cc_x = 20`、`cc_y = 21`、`channel = 0`（**不撞推子的 CC1**）。

**顺带**：推子的 `{type:'set_target'}` 也改成"内存 + 落盘"（同一类记忆，同一处实现）。

## 5. 不做（非目标）

- 不做预设/多套 CC 配置（一个模块记住一组就够）。
- 不做多点：双指各控一个轴、双指缩放、多指手势。
- 不做网格、轨迹、轴反转开关、数值步进微调。
- 不做 PC 端镜像或编辑器（X/Y 没有"布局"这种东西；PC 端状态行能看到它在发的 CC，那是既有能力）。
- 不做 14-bit CC、不做曲线/死区/平滑（插件侧自己做）。
- 不做状态回读（DAW 里那个参数现在在哪 —— 需要 Bridge 具备 MIDI 输入，是另一条链路，spec 里明确不做）。

## 6. 验收

| # | 验收项 | 怎么测 |
|---|--------|--------|
| 1 | 一个触点同时产出两条 CC（X / Y 各一条），通道与 CC 号来自配置 | 离线断言（桩 WebSocket 抓消息 + Bridge 侧 `send_cc` 记录） |
| 2 | 只动一个轴时**只发那一条**；值没变档就不发；两条之间遵守 4 ms 下限 | 离线断言 |
| 3 | 未触碰前**不发任何值**；首次落点才开始发（且从中心补间过去） | 离线断言（首帧无消息、落点后出现两条） |
| 4 | 抬起**不产生任何消息**（没有归零/归中） | 离线断言 |
| 5 | 第二根手指落下时 Position 不变、不发值 | 离线断言（两次 pointerdown，值只跟第一根走） |
| 6 | Landing 补间约 40 ms 内把两个值推到触点；Drag 期间每一档都发、无插帧 | 离线断言（按时间步进驱动，数消息与值序列） |
| 7 | 回中：Position 到正中（走补间），结束时发出两个中心值 | 离线断言 |
| 8 | 冻结期间一个值都不发但 Marker 跟随；解冻发一次当前值 | 离线断言 |
| 9 | 断连时拖动不发值、显示「未连接」 | 离线断言（桩 `ws.onclose`） |
| 10 | CC 号/通道改完立刻生效、写进 `xy.json`；下次启动读回；非法值退回默认 | 离线断言（Bridge 侧，临时文件） |
| 11 | 真机：**跟手感**（拖着走无滞后）、**位置标记**停在松手处、正方形不顶边、回中/冻结好用、插件里两个参数同时动 | **真机 yes/no** |
| 12 | 真机：确认插件 Learn 到的两个 CC 与页面显示一致（改号后无需重启 Bridge） | **真机 yes/no** |

## 8. 实施顺序

1. Bridge：`xy.json` 读写 + `kind:'xy'` 分支（两条 `send_cc`）+ 推子 `set_target` 落盘。
2. 手机端：`/xy.html` + `xy.js`（正方形控制面、Marker/十字线/数值、Landing/Drag、回中/冻结、断连态、CC 配置）。
3. 首页加第三张卡片；另两个模块显示名改成 Digital Fader / Shortcut Pad。
4. 测试、截图、真机一轮。
