## 1. 与旧 Mode C 的根本差异

| | 旧（shake → bend） | 本方案（vibrato） |
|---|---|---|
| 语义 | 摇晃**幅度**映射为**静态**弯音量（停在偏离中心的音高） | 摇晃**波形**映射为**绕当前音**的周期性偏移 |
| 中心 | 需要自动零位/重力估计/降级路径 | **高通天然去直流**，中心自动精确 |
| 刻度 | 自适应或固定值（多套机制） | 一次标定后恒定 |
| 用户动作 | 晃一下 = 弯一下 | 持续揉弦 |

**旧实现里最复杂、最易出 bug 的部分（自动零位、重力估计、降级路径、冷启动、自适应估计器）
在本方案中结构性消失**：直流（重力、陀螺零偏、恒定倾斜）在高通转角处的增益为 0，
不揉弦时输出天然为 0 = 精确 8192。

## 2. 已确认的设计决策

| # | 决策 | 依据 |
|---|------|------|
| 1 | **跟随式映射**：带通输出直接驱动 bend；不做受驱合成振荡器 | 真揉弦的幅度与频率都在变化，跟随式原样保留两者；合成振荡器会抹平变化 |
| 2 | **跟手优先**的滤波取向 | 用户要求 |
| 3 | **沿用现有架构**：浏览器 + PC Bridge（WebSocket） | 用户要求；60 Hz 采样对本频段足够（见 §5.2） |
| 4 | **深度 = 比例**（`k × 信号`）+ 软上限；`k` 一次标定，**运行时不自适应** | 用户要求；且自适应会切断力度与输出的对应关系（上一版实测教训） |
| 5 | **永远输出**（不做音符感知） | 用户要求 |
| 6 | 标称深度 **±15 cents**（Nuendo 显示 ±7.5） | 真机试听后从 ±30 减半：±30 在 DAW 里摆幅过大；古典小提琴揉弦常见 ±10–25 cents，深度还可用「倍率」整体缩放 |
| 7 | 高通转角 **1.5 Hz**（做成滑杆） | §5.3 实测：比 4 Hz 省 40 ms 延迟，代价可忽略 |
| 8 | 输出 **250 Hz 插值**，默认开 | §5.4 实测：不插值是 8.6 cents 的波形误差 |
| 9 | **不做极性开关** | 听觉对调制**相位**不敏感（上升先/下降先听不出），已确认 |

## 3. 单位换算（必须新增 DAW 弯音范围设置）

Nuendo 的 bend 轨显示 **±100 = ±2 半音 = ±200 cents**（默认设置）。于是：

| 音分 | 14-bit 计数 | Nuendo 显示 |
|------|-------------|-------------|
| ±10 | ±410 | ±5 |
| **±15（标称）** | **±614** | **±7.5** |
| ±50（上限） | ±2048 | ±25 |

- `1 cent = 8192 / (100 × dawBendSemitones)` 计数；
- 新增设置 `dawBendSemitones`（默认 **2**）。**若在 Nuendo 里改了弯音范围，必须同步改这里**，
  否则同样的计数会对应不同的音分（±2 → ±12 半音会让 ±30 cents 变成 ±180 cents）。
- 手机 → Bridge 仍送 `value ∈ [0,1]`：`t = 0.5 + cents / (200 × dawBendSemitones)`。
  ±50 cents 只占 PB 全量程的 25%（`t ∈ [0.375, 0.625]`）——这正是揉弦应有的比例。
- **UI 一律显示 cents**（以及等价的 Nuendo 显示值），不再用百分比。

## 4. 信号链

```
devicemotion（60 Hz，事件时间戳驱动）
 │
 ├─① 双源带通
 │    gyro  = rotationRate  (°/s；原始陀螺，无姿态融合延迟)
 │    accel = acceleration  (线性加速度；缺失时可退回 includingGravity)
 │    两源各自过同一条带通，比较带内能量 → 择优，切换时 50–100 ms 交叉淡化
 │
 ├─② 轴选择：6 个候选（3 陀螺 + 3 加速度）取带内能量最大
 │    迟滞（避免抖动切换）+ 交叉淡化（避免音高跳变）
 │
 ├─③ 带通：2 阶高通 1.5 Hz（去直流/漂移/重力）+ 1 阶低通 15 Hz（保证带限，供插值）
 │    群延迟 11.5 ms @6.5 Hz
 │
 ├─④ 深度：cents = softLimit(k × signal)
 │    k：一次标定（正常揉弦 → ±15 cents）
 │    软限幅：35 cents 以下严格线性，35→50 平滑压缩，**上限 50**
 │
 ├─⑤ 死区（作用于**幅度**，不是瞬时值）
 │    运行幅度 = **滑窗峰值**（近 150 ms 的 max|信号|，与频率无关）
 │    低于阈值 → 40 ms 斜坡回 0（精确 8192，消息流静默）
 │
 └─⑥ 输出：250 Hz 循环 + **三点二次插值**（1 样本延迟，插值后再钳制到 ±cap）
      cents → t = 0.5 + cents/(200×dawBendSemitones) → WebSocket
      Bridge 无需改动：kind:'pb' / value_kind:'bipolar'（ADR 0003）
```

### 4.1 为什么不把两路信号相加

陀螺单位是 °/s、加速度是 m/s²，**直接相加没有物理意义**。做法是：
**同一单位内（3 轴之间）比较能量选轴；跨单位则择优 + 交叉淡化**。
若将来需要真正的双源融合，正确做法是**各自定标后相加**（用各自的一次性增益把
"正常揉弦"都定到 ±15 cents，再相加，可提升约 3 dB 信噪比），列为 Phase 2 可选项。

### 4.2 轴与事件的实现要点

- `rotationRate.alpha/beta/gamma` 分别对应 **z / x / y 轴**（DeviceMotionEvent 规范），
  实现时不要错配轴标签。
- 用 **`event.timeStamp`** 作为时间基准，**不要假设事件等间隔**：WiFi/主线程抖动会让
  到达间隔不均，用等间隔假设会在插值里引入时间误差。

## 5. 关键数字（均为实测/计算，非估计）

### 5.1 滤波器对比（fs = 60 Hz，群延迟 @6.5 Hz）

| 方案 | 群延迟 | @5Hz | @7Hz | 抑制 @0.5Hz | @1Hz |
|------|--------|------|------|-------------|------|
| HP2 4Hz + LP2 11Hz | **51.4 ms** | −1.6 dB | −0.9 dB | −36 dB | −24 dB |
| **HP2 1.5Hz + LP1 15Hz（采用）** | **11.5 ms** | −0.4 dB | −0.7 dB | −19 dB | −7.9 dB |
| HP2 2.5Hz + LP1 15Hz | 18.3 ms | −0.6 dB | −0.7 dB | −28 dB | −16 dB |

**为什么低转角更好**：直流在 HP 的增益为 **0**（完全去掉重力与陀螺零偏）；
低转角放松的只是 0.5–2 Hz 的慢速动作，而这类动作**幅度本身很小**，
−19 dB 后折算到音高只有零点几 cents。**代价可忽略，收益是 40 ms 延迟。**

### 5.2 采样率

`devicemotion` 无采样率参数；真机实测 **60.0 Hz**（证据：`docs/json.json` 标定窗
5000 ms / 300 样本）。60/7 ≈ 8.6 样本/周期（奈奎斯特 4 倍以上），
**保真度足够，受限的是输出台阶**——而台阶与采样率可以解耦（§5.4）。

### 5.3 输出台阶（cents）

| 深度/频率 | 变化率 | 60 Hz 直出 | 125 Hz | 250 Hz |
|-----------|--------|-----------|--------|--------|
| ±30c @6Hz | 1131 cents/s | 18.8 | 9.0 | **4.5** |
| ±30c @7Hz | 1319 | 22.0 | 10.6 | **5.3** |
| ±50c @7Hz | 2199 | 36.7 | 17.6 | 8.8 |

浏览器输出循环上限为 **250 Hz**（`setInterval` 被规范钳制在 4 ms；rAF 仅 60 Hz）。

### 5.4 插值方式对比（±30 cents、7 Hz、采样 60 Hz、输出 250 Hz）

| 方式 | 插值延迟 | 波形误差 (RMS) | 深度脉动 |
|------|----------|----------------|----------|
| 不插值（零阶保持） | 16.7 ms | **8.6 cents** | ±0.02 |
| 线性 | 16.7 ms | 1.03 cents | ±0.45 |
| **三点二次（采用）** | **16.7 ms** | **0.37 cents** | ±0.03 |
| 四点三次 | 33.3 ms | 0.13 cents | ±0.03 |

**二次插值在零额外延迟下把误差降到线性的 1/3**：它需要 `x[i-1], x[i], x[i+1]`，
而插值点已在过去 1 个样本，因此前瞻是免费的。三次要多一个样本、延迟翻倍，不值得。

### 5.5 延迟预算

> ⚠️ 下表是**设计估算**，P3–P5 实测后已被 §13.4 修正：带通在 6 Hz 处是**相位超前**
> （−5.4 ms），插值相对"补零保持"只多花**半个采样**（8.4 ms）。真实相位延迟 ≈ **15 ms**。

| 环节 | 延迟（估算） |
|------|------|
| 传感器采样 60 Hz（平均等待） | 8.3 ms |
| 带通 HP2 1.5Hz + LP1 15Hz | 11.5 ms |
| 二次插值（1 样本因果延迟） | 16.7 ms |
| WiFi + Bridge（实测） | 2.0 ms |
| DAW 块量化（平均，128@48k） | 1.3 ms |
| **合计** | **≈ 39.8 ms** |

按需可降到 ~23 ms（关插值），但会带来上述 8.6 cents 的波形误差。

## 6. 深度、上限与死区

**软限幅**（35 cents 以下严格线性，因此标称点不受影响；渐近到 50 且永不越过）：

```
softLimit(c) = sign(c) · min( knee + range·(1 − exp(−(|c|−knee)/range)), cap )
              knee = 35, range = 15, cap = 50
```

**死区必须作用于幅度**：对瞬时值做死区会把正弦峰顶削平，音高变成方波状。
正确做法是**滑窗峰值**（近 150 ms 内 max|信号|，与信号频率无关）低于阈值 →
40 ms 斜坡回 0。这样静止时输出**精确**为 8192，Bridge 因"值未变化"而**不发消息**。

> 实现时先用的是"整流 + 低通"，它只在信号频率远高于低通转角时才等价于幅度：
> 对更慢的信号（手以 0.2 Hz 倾斜）它跟踪的是瞬时值，再乘 π/2 峰因数就高估 57%，
> 导致死区误开、慢速倾斜直接入音。滑窗峰值消除了这个频率依赖。

**不做任何运行时归一化**：`cents = k × 带通输出` 本身即"用力越大弯越多"，
先提取幅度再乘回去会互相抵消。

## 7. 标定与调参

**一次性标定**（P4 已实现为 `PhoneMidiVibrato.calibrate(samples)`，存储键
`pm.vibrato.cal.v1`，由 `web/vibrato-lab.html` 调用）：

1. 用户以**正常力度**揉弦 5 s（可短到 2.5 s，再短判 `too_short`）；
2. 每个通道都走**与运行时同一条带通链**（unity gain），统计量用**选择器自己的
   150 ms 滑窗峰值**，取中位数 → 吸收带内衰减（§12.3），也让"电平"与运行时口径一致；
3. 选源：陀螺通道电平 ≥ `calibMinLevelCents` 就用陀螺（旋转传感器直接测揉弦），
   否则退回加速度（无陀螺设备的兜底）。**不跨单位比较**——°/s 与 m/s² 不可比；
4. 该源内电平不低于最强通道 −20 dB 的通道标为可用，其余 `gain = 0`；
   每个可用通道都给 `gain = 15 cents / 该通道电平`，**所以换轴不改变深度**；
5. 主通道的**向上过零点间隔中位数** → 实测揉弦频率，必须落在 3–11 Hz，否则判 `rate`；
6. 同时得到实测采样率（`fs`），写回引擎的 `nominalFs`，使插值延迟与实际一致。

失败原因是**可判定的中文提示**（`too_short` / `too_quiet` / `rate`），不是静默失败。

**调参**（`/vibrato-lab.html`，即时生效、无需重新标定）：高通/低通转角（改动会重建滤波器）、
软限幅 knee/cap、静音门限与斜坡步数、最小发送步进、输出频率、插值开关、
源与轴的手动锁定、DAW 弯音半音数。

## 10. 风险与限制

| 风险 | 说明与对策 |
|------|-----------|
| 60 Hz 下 7 Hz 的峰值估计偏低 ≤4.9% | 标定用同一链路测量，误差被 k 吸收，不影响使用 |
| 手抖/生理震颤 8–12 Hz 与揉弦频段重合 | **无法用滤波器分离**，只能接受——这也是它"像人"的原因；深度上限兜底 |
| 后台标签页定时器被节流到 1 Hz | 用 Wake Lock（`navigator.wakeLock`）并提示保持前台 |
| 部分设备 250 Hz 定时器被进一步钳制 | 调试页实测并显示**实际输出率**；不足时自动降级并告警 |
| `rotationRate` 缺失或恒为 0 | 走加速度路径；带通已自动去重力，因此 `includingGravity` 也可作最后兜底 |
| DAW 弯音范围与设置不一致 | §3 的 `dawBendSemitones` 必须与 Nuendo 一致；UI 显示换算后的 cents |
| 60 Hz 事件的**抖动** | 用 `event.timeStamp` 作时间基准，不假设等间隔 |

## 12. 实现与验证记录（P1 + P2 已完成，2026-09-18）

代码：`web/vibrato.js`（纯函数，无 DOM，Node 中可直接加载）。
验证：合成信号驱动整条链，**16/16 通过**。

### 12.1 实现中发现并修正的三个问题

| # | 问题 | 现象 | 修正 |
|---|------|------|------|
| 1 | 二次插值的索引差一位：把括号区间的**上端**当作三点中心 | 需要多一个样本 → **75% 的输出悄悄退化为线性插值**（回退计数 746/1000） | 以括号区间的下端为三点中心（`x[j-2], x[j-1], x[j]`）：回退 **0**，形状畸变 6.7 → **0.10 cents** |
| 2 | 死区幅度估计频率相关（整流+低通×π/2） | 慢速倾斜（0.2Hz）被高估 57%，死区误开、倾斜直接入音 | 改用**滑窗峰值**（150 ms） |
| 3 | 上限在插值**之前**施加 | 深限幅后波形接近方波，二次插值在拐角**过冲**：实测 **62.4 cents 越过 50 上限** | 插值后再钳制到 ±cap，实测最大恰为 **50.00** |

另：滤波器在首个样本处**预置到稳态**（HP 的 z1/z2 直接解出），
否则"0 → 重力"的阶跃会产生约半秒的音高瞬态。实测首 0.5 s 输出恒 0 ✓。

### 12.3 带通的实际增益（标定会吸收，但需知道）

| 频率 | \|H\| |
|------|------|
| 5 Hz | 0.954 |
| 6 Hz | 0.938 |
| 7 Hz | 0.920 |
| 8 Hz | 0.899 |

带内波动 **0.52 dB**（5→8 Hz）。标定在同一链路上测量，因此**标称深度精确**；
只是"同样力度、不同揉弦速率"会有 ±0.3 dB 的深度差异——听不出来。
曾评估把低通转角提到 25–30 Hz（波动降到 0.14 dB、延迟省 2.6 ms），
但高频内容的插值误差会变大，故**保持 15 Hz**。

### 12.4 必须知道的特性：慢速动作会入音

高通转角决定了"什么算揉弦"：

| 手的动作 | 透过率（HP2 @1.5Hz） | ±3 单位摆动的输出 |
|----------|----------------------|-------------------|
| 0.2 Hz 倾斜 | 2% | 0（被死区挡住） |
| 1 Hz 摆动 | 41% | ±36 cents |
| 2 Hz 摆动 | 87% | ±49 cents（进入软限幅） |
| 3 Hz 摆动 | 97% | ±50 cents（满深度） |

**这是 2–3 Hz 与 5–8 Hz 太接近导致的物理限制**，任何滤波器都无法只压前者不压后者
（HP 提到 4 Hz 时，3 Hz 仍透过 49%，而 5 Hz 揉弦要损失 1.6 dB、延迟增到 ~27 ms）。
实际风险有限：±3 单位是指"标定参考幅度的 3 倍"，那是一次**刻意的、幅度很大的**手腕动作，
正常演奏不会无意做出。**如需更保守，把高通转角调到 2.5–4 Hz**（延迟 18–27 ms）。

## 14. 深度减半 + 倍率（2026-09-19，真机试听后）

真机反馈：**摇晃本身很丝滑，但映射到 DAW 的值动态过大**。判断成立——±30 cents 对揉弦偏大
（古典小提琴揉弦常见 ±10–25），于是把标称深度定为 **±15 cents**，并把手感交给一个可调倍率：

| 改动 | 说明 |
|------|------|
| `DEFAULTS.nominalCents` 30 → **15** | 标定契约改成"正常揉弦 = ±15 音分"，Nuendo 显示 ±7.5 |
| 新增 `DEFAULTS.depthTrim`（默认 1.0） | **作用于限幅之后**的输出倍率：0.5 = 整体减半（含上限 → ±25），2 = 加倍（硬上限仍锁在 ±50） |
| 门限仍看**手** | `core` 把"手劲"（`effort`）与"输出深度"（`amplitude = effort × trim`）分开：调倍率不会改变"多大动作才算在揉弦" |
| 上限随倍率缩（trim ≤ 1） | 插值后的钳位用 `cap × min(1, trim)`，否则深限幅波形的插值过冲会越过"减半后的上限"（实测 x0.5 时冲到 31.21，修好后恰为 25.00） |
| 旧标定自动换算 | 标定 payload 记录拟合时的 `nominalCents`；读到旧的（无此字段 → 视为 30）就在加载时把 gain 乘 `15/30`，界面上提示"已自动缩放"，**不需要重新校准** |
| 主页面新增「深度」输入框 | 0.25–2.00，演奏中直接改，写入 `pm.vibrato.settings.v1`，下次自动带上；调试页也有同名滑块 |

## 15. Bug：摇晃停止后 bend 没有回中（2026-09-19 真机反馈）

**症状**：停止摇晃后，DAW 里的弯音停在某个值上，不回中心。

### 15.1 复现（合成信号，`tests/vibrato.test.mjs`）

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 6 Hz 揉弦 1.5 s，随后接 1.2 Hz 的收手慢摆 | 停在 **10.74 cents** | **0.00**（400 ms 内归中） |
| 只有 2 Hz、25 °/s 的慢摆 | 持续 **22.06 cents** | 0（0.22 s 内 latch 掉） |
| 只有 3 Hz、22 °/s | 持续入音 | 0 |
| 只有 0.9 Hz | 持续入音 | 一次 ≤8 cents 的上冲后归 0 |

### 15.2 原因

1. **门限只看幅度**：1–3 Hz 几乎原样穿过 1.5 Hz 高通（§13.6 的泄漏表：2 Hz 93%、3 Hz 102%），
   而"停止摇晃"时手并不会瞬间静止（收手、放下手机都是 1–2 Hz 的慢动作）。幅度门限因此一直
   开着，输出就成了"一个静态偏移"——听感正是"没回中"。
2. **弯音在 DAW 里是绝对状态**：手机一旦不说话（锁屏、WiFi 抖动、页面冻结/关闭、浏览器节流），
   最后一条 PB 会一直留在 DAW 里。此前只有引擎内部的"停摆保护"（250 ms 无样本 → 0），
   它救不了"定时器停了/连接断了"的情况。
3. **加速度通道把"转动手机"当成了手部晃动**（真机上最可能的主因）：六轴里陀螺与加速度同时可选，
   而加速度通道的默认 gain 是陀螺的 10 倍（§6 的估算）。手机转动时重力在各轴间缓慢重分配，
   这在原始加速度上是一条**斜坡**，穿过高通后变成**持续偏移**——用户"停止摇晃"时往往仍在
   转身/低头看屏幕，于是弯音一直不回中。改用陀螺优先后这条路径消失。

### 15.3 修复（最终版）

| 位置 | 改动 |
|------|------|
| `web/vibrato.js` | **忠实映射**：门限只是"手有没有动"的静止检测（幅度低于 `gateCents` → 精确 0）。**不再判断"这是不是真揉弦"**——任何超过门限的动作都原样送成音高，慢速倾斜也是慢速音高。手停下来 → 静止输入经高通即为 0 → 门限关闭 → 精确 8192 |
| `web/vibrato.js` | **自动选源优先陀螺**：设备报告了 rotationRate 就只用陀螺通道（引擎按到手的数据解析 `sourceMode:'auto'`）。加速度通道只留给没有陀螺的设备——否则手机转动时重力在轴间的**缓慢重分配**（那是姿态变化，不是手的晃动）会以斜坡形式穿过高通，变成一个持续偏移 |
| `web/vibrato.js` | 保留**手动速率测量**（半周期中位数）但**只用于显示**，不参与任何判定；调试页显示"手动速率 N Hz（仅显示）" |
| `bridge/server.py` | **弯音守护（dead-man）**：手机超过 `--pb-idle-ms`（默认 500 ms）没发消息且通道仍弯着 → 自动发 8192 并告警；断连时归中所有弯着的通道；`--pb-idle-ms 0` 关闭 |
| `web/app.js` | `visibilitychange`→隐藏、`pagehide` 时立刻发一条中心值（赶在浏览器节流之前） |

> **走过的弯路（记下来避免重复）**：针对"没回中"，我一度加过**振荡判定**——门限除了幅度还要求信号
> 确实在 3.2 Hz 以上摆动，否则关门并 latch，并配 0.22 s 的"起振豁免窗口"。它确实让慢动作不再持续入音，
> 但**与产品定位冲突**（见 §16）：它把"慢速但有意的动作"也判成非法，而起振口子又带来一段上冲。
> **已整段移除**，`vibratoOnly` / `oscMinHz` / `oscArmSec` 三个参数不再存在。
> 教训：把"判定什么是合法演奏"塞进 DSP，等于把艺术决定交给阈值。

### 15.4 现在成立的保证（`tests/vibrato.test.mjs`）

| 场景 | 结果 |
|------|------|
| 2 Hz 摆 2 s 后手彻底不动 | 之后 350 个 tick **全部精确 0**（2.53 s 处归中） |
| 静止但六个轴都有噪声 | 0 条消息、输出精确 0，自动选源 = `gyro` |
| 慢速动作是否被"静音" | **不会**：2 Hz → 6 Hz 深度的 **93%**、0.9 Hz → 36%（只由高通决定，与门限无关） |
| 传感器停摆 250 ms | 一次性归中，之后静默 |
| 手机静默 / 断连 | Bridge 守护归中并打日志 |
| 速率测量 | 5.00 Hz 实测（仅显示，528 条消息照常发送） |

慢动作"漏进来"不是缺陷，而是**这个乐器的定义**（见 §16）：`hpHz` 是唯一的旋钮，
调高 = 只跟随更快的动作，调低 = 更宽容。

## 16. 先行项目调研与产品定位（2026-09-19）

用户要求先去查已有的"摇晃输入 MIDI"项目。结论直接决定了 §15 的最终修法。

### 16.1 现成的三条路

| 范式 | 代表 | 手停下时 |
|------|------|----------|
| **A 绝对姿态 → 参数** | TouchOSC 陀螺控件、一大批 ESP32/IMU→CC 固件、[专利 US8802958](https://patents.google.com/patent/US8802958/en) | 值**保持**（必须另做回中） |
| **B 阈值触发** | [MidiWrist Unleashed](https://uwyn.com/midiwrist-unleashed/)（Apple Watch，Geert Bevin）：运动数据带阈值触发，精细参数交给表冠 | 离散消息，不连续 |
| **C 运动强度 → 揉弦量（生成式）** | [Genki Wave 的 Vibrato](https://genkiinstruments.github.io/wave-for-music/functions/vibrato/)：*"Vibrato is the side to side movement of your hand. It uses acceleration so it depends on how fast you move how much Vibrato you add."* | 深度→0，**回中是结构性的** |
| **D 跟随式带通 → 直接当弯音**（本项目） | 搜遍 GitHub 未找到同类实现 | 由高通决定：静止 → 0 |

最接近本项目架构的浏览器方案：[MaxAlyokhin/audio-motion-interface](https://github.com/MaxAlyokhin/audio-motion-interface)（★51，手机传感器→网页合成器）、[JimAnkrom/sway](https://github.com/JimAnkrom/sway)（★13，app-free、设备无关的控制）；摇晃类有 [bassjansson/shakemidi](https://github.com/bassjansson/shakemidi)。国内也有同样想法的 DIY（手机→MIDI CC 表情/颤音/弯音，用 Logic Pro Scripter 当映射层）。研究侧（如 [TISMIR 用手表 IMU 研究小提琴运弓](https://reference-global.com/article/10.5334/tismir.216)）把揉弦当作**要检测的特征**，而不是把信号本身当音高。

### 16.2 我们的定位（用户决定，2026-09-19）

> "放弃去判断哪些动作是真的揉弦，而是忠实地输出所有的手部摇晃。这种条件下的特殊揉弦一定是和普通揉弦不一样的，
> 100% 的弦乐音源本身就带有揉弦功能，如果我需要一个普通的揉弦那么我可以直接用揉弦功能即可。"

1. **本项目不是揉弦模拟器，是"手势 → 弯音"的表达乐器**，做的是音源自带揉弦做不到的事（不规则的、随动作变化的、有意图的推拉）。
2. **因此不采用范式 C（生成式）**：那会把手的动作压缩成"深度"一个标量，丢掉手势本身——而手势正是要卖的东西。
3. **因此不做"合法性判定"**：慢速动作、不规则晃动都应忠实送出（§15.3 的弯路由此而来）。
4. **回中靠物理而不是判定**：高通让静止输入为 0，门限把静止锁成精确 8192；手机不说话时由 Bridge 守护兜底。
