# 平板专用页（`/tablet.html`）— 方案与步骤分解

> 用户需求（2026-10-23）：手机屏小、一屏放不下多少按钮；希望网页服务能**自己判断**当前是平板还是手机，
> 给平板一个专用网页：**没有 Digital Fader**（平板拿在桌上的姿势不适合抬手/翻腕/摇晃），只保留
> **Shortcut Pad** 与 **X/Y Pad**；平板上的 Shortcut Pad 把手机的 **6 页 × 8 格 = 48 个按钮平铺一页**
> （48 个方形按钮），X/Y 在**另一页**并**自适应平板尺寸**。
>
> **同日修订**：第一版按"8 列 × 6 行、一行 = 一页"做，用户看到后要求**和手机一样**——六页保持各自的
> 2 列 × 4 行、左右并排（用户给的图：12 列 × 4 行、每 2 列一组、组间留更宽的缝）。下面以修订版为准。

---

## 1. 定位

| | 手机（现在的页面） | 平板（新页面） |
|---|---|---|
| 入口 | `/` → 选模块 | `/` **自动**进 `/tablet.html` |
| 模块 | Digital Fader / Shortcut Pad / X/Y Pad | Shortcut Pad（48 格） / X/Y Pad |
| Shortcut Pad | 2 列 × 4 行，6 页页签翻页 | **六页左右并排**：每页仍是 2 列 × 4 行，页间留更宽的缝（= 12 列 × 4 行） |
| X/Y Pad | 页面里一块最大 420 px 的正方形 | **另一个视图**，正方形取舞台里能放下的最大尺寸 |
| 数据链路 | `/ws` + `pad_layout` + `{kind:'trigger'}` / `{kind:'xy'}` | **完全相同**（协议零改动，DAW 映射零改动） |

平板仍然是**哑显示端**：布局由 Bridge 下发（Layout Push），按一下只上报一个触发编号，不认识宏、不读传感器。

---

## 2. 已定的决策

| # | 决策 | 依据 |
|---|------|------|
| **T1** | 设备判定用**视口短边**（`min(innerWidth, innerHeight)`），门槛 **640 CSS px**；**不用 UA** | iPadOS 13 起 Safari 的 UA 自称 Macintosh，按 UA 判平板必然把 iPad 认成电脑；而短边在手机上不会超过 ~430（折叠屏展开也 < 640），iPad mini 竖屏 768 就已命中 —— 横竖、装不装 App 壳都不影响 |
| **T2** | 分流放在**页面侧**（`web/device.js`），页面用 `<html data-route="home\|phone\|tablet">` 声明自己是谁 | Bridge 只能看到 HTTP 请求；设备事实（视口、方向）只有浏览器知道。判定脚本同步放在 `<head>`，在**首次绘制前**完成跳转，不会先闪一下手机版 |
| **T3** | 分流规则：首页 / 手机专用页 → 平板进 `/tablet.html`；平板页 → 手机进 `/pad.html`；**已经在对的页面上什么都不做** | 一个网址两端都能用，不需要用户记两个地址。用 `location.replace`，不让"平板打开 / 被送走"在后退栈里留死循环 |
| **T4** | 留**覆盖开关**：`?device=phone` / `?device=tablet` / `?device=auto`，写进 `localStorage` | iPad 分屏、Stage Manager 下窗口短边可能 < 640，会被判成手机；桌面浏览器短边通常 ≥ 640 会被判成平板。这两种情况都需要一条人工退路；页脚都有"手机版 / 平板版"链接 |
| **T5** | 平板用**独立页面** `/tablet.html`，不给 `pad.html` 加媒体查询 | 48 格的**结构**与手机的 6 页 × 8 格不同（没有页签、一屏到底、字号跟格子算）；塞进一个文件会让两边互相牵制。而格子本身（建格/绘制/按下/松开/离线拒按/震动/松手痕迹）仍在 `padgrid.js`，三个宿主**共用同一份实现** |
| **T6** | **六页左右并排**：第 p 页占据第 2p、2p+1 两列的第 0–3 行（每页仍是一个 `createGrid(page = p)` 的 2×4 网格）；触发编号 `p × 8 + s` 与手机**逐格相等** | 用户给了图并明确"和手机一样"：页内的形状、编号、按下行为都不变，只是把页签换成了"六页并排"。编号由 padgrid 按页号算，所以 Bridge、协议、DAW 侧（Note 36–83）**一个字都不用改**（ADR 0004） |
| **T7** | 格子**尺寸由 JS 算**：`size = min((可用宽 - 6×页内缝) / (12 + 5×0.5), (可用高 - 3×页内缝) / 4)`；页间距 = 0.5 个格子；每页宽高由同一个 size 推出 | 这是"48 个**方形**按钮"的硬保证：只靠 `1fr + aspect-ratio` 在横屏/竖屏下总有一种会变成扁矩形。页间距按格子大小走，和用户给的图一样（约为格子的半格）。`ResizeObserver` + `resize` + `orientationchange` + `load` 都会重量一次 |
| **T8** | X/Y 用**同一份** `xy.js`（按 id 取元素），`tablet.html` 里备齐同样的 id；**横屏时控制项在右栏**（300 px），竖屏上下排；正方形面 = 舞台能放下的最大尺寸 | 不允许出现"手机一套 X/Y 行为、平板另一套"。横屏右栏是为了把 pad 撑到几乎整个高度——照手机那样在 pad 下面叠四行，pad 会被压小一半 |
| **T9** | 顶栏两个视图（**48 格 / X/Y**）切换；切走时 `releaseAll()` 先松开按住的格 | 格子被 `display:none` 藏起后 `pointerup` 可能送不到，DAW 里会留一条永远关不掉的 Note（与手机翻页同一条教训） |
| **T10** | 平板**没有** Digital Fader：首页不列、`/fader.html` 在平板上直接回 `/tablet.html` | 用户明确不需要；平板放在桌上时抬手/翻腕/摇晃的动作方式不成立 |
| **T11** | 深链接 `?view=xy`（或 `#xy`）直接打开 X/Y | 截图与收藏用；无状态，不影响默认视图 |

## 3. 行为规格

### 3.1 判定与分流

- 打开 `/`：短边 ≥ 640 → `/tablet.html`；否则留在模块列表。
- 平板上打开 `/pad.html`、`/xy.html`、`/fader.html`：都回 `/tablet.html`（手机版对平板没有意义，推子更是没有）。
- 手机上打开 `/tablet.html`：回 `/pad.html`（不让 12 列的布局铺在手机屏上）。
- 覆盖参数优先于屏幕尺寸，并被记住；`?device=auto` 清掉记忆、回到自动判断。
- 判定只在**加载时**做一次：平板上把它拖进分屏不会中途换页（中途换页会丢掉正在按的键）。

### 3.2 Shortcut Pad（48 格）

- **六页左右并排，一屏到底**：第 p 页（p = 1…6）是一个 2 列 × 4 行的网格，页与页之间留一道
  约为半格的缝。整体读起来是 12 列 × 4 行，每组 2 列就是手机的一页。
- 每格：文字 + 颜色 + 字色（`ink`）全部来自 Bridge 的 `pad_layout`；缺字段退回白底深字。
- 按下：只发 `{kind:'trigger', id, phase:'down'}`；抬起配一条 `up`；一格同时只发一条 down
  （与手机共用 padgrid.js 的实现，含同一格的第二根手指、离线拒按、震动 25 ms、松手 220 ms 痕迹）。
- 悬停提示 `title` = `第 N 页 · 页标题`（页标题没有位置常驻）。
- 未连接：格子变灰且**代码里也拒按**（与手机同一条：宁可看起来不能按，也不做"悄悄不发"）。

### 3.3 X/Y Pad

- 与手机是**同一份** `xy.js`：绝对语义、松手保持、Landing 40 ms 补间、Drag 零平滑、
  回中 / 冻结、两个快速预设（弦乐表情 / X/Y Pad）全部一致。
- 面是舞台里最大的**正方形**；横屏右栏放控制项（回中/冻结、读数、预设、CC 号、通道），竖屏上下排。
- 断连：面变灰 + `pointer-events:none` + 读数「未连接」（同手机）。

### 3.4 连接

- 平板页与手机一样直接连 `wss://<bridge>/ws`，断线 2 秒重连；连接时 Bridge 自动推 `pad_layout`。
- 平板页会同时开两条 WebSocket（面板一条、X/Y 的 `xy.js` 一条），与手机端"每个页面各连一条"的现状一致；
  Bridge 的客户端集合本来就支持多端并存。

---

## 4. 协议与数据

**没有新增任何消息。** 平板发的就是手机那两条：

```json
{ "kind": "trigger", "id": 47, "phase": "down" }
{ "kind": "xy", "x": 127, "y": 0, "cc_x": 20, "cc_y": 21, "channel": 0 }
```

- `id` 仍是 `0..47`（= 手机第 p 页第 s 格的 `p×8+s`），Bridge 仍按 `36 + id` 发 Note。
- 布局仍是 Bridge 单向下发的 `{"type":"pad_layout", ...}`，平板只读不写。

---

## 5. 不做（非目标）

- 平板上的 Digital Fader（A/B/C 三个模式都不出现）。
- 页签/翻页：六页并排、一屏到底，不做"平板也分页"。
- 两套布局：横屏与竖屏用同一套"六页并排"，只是整体居中（横屏格子更大、竖屏更小、上下留白）。
- 平板端编辑布局：仍在 PC 端编辑器里改，平板只显示。
- 状态回读（DAW → 手机）：与手机版同一条 v1 非目标。
- 按设备给不同的按钮集合：48 个按钮就是手机的 48 个，一个不多一个不少。

## 7. 开放问题

- **短边 640 这条线**：iPad 分屏（约 507）与 Stage Manager 小窗会被判成手机，需要 `?device=tablet`
  或页脚开关。要不要按"有没有触摸 + 宽高比"再判一次，等真机用出问题再说。
- **桌面浏览器按平板处理**（短边通常 ≥ 640）：在 PC 上打开 Bridge 地址看到的是平板页。可以用
  `?device=phone` 看手机版；若以后觉得别扭，可以给桌面单独一档。
- **页标题**：现在靠"每组 2 列 = 一页"和悬停提示，没有常驻的页标题；若实际用起来分不清第几组，
  再在每组上方加一行小标题（会占掉约 20 px 高度）。
- **竖屏**：12 列并排在 820 宽上与横屏比格子明显更小（约 51 px）。要么建议横屏使用，要么以后给竖屏
  另排一种折法（例如 6 页分两行）——先看真机使用习惯。
- **真机**：iPad 的 `100dvh`、安全区、Safari 的触摸事件与震动（iPad 没有马达，`navigator.vibrate`
  静默跳过）都还需要真机看一遍；当前结论来自 Edge 无头截图与桩测试。
