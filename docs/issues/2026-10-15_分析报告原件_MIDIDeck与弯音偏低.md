## 一、结论速览

**是的，MIDI Deck 具备造成这个现象的完整能力，而且时间与数值都对得上。**
但它属于「触发者」，不是「唯一可能来源」——pitch bend 在 DAW 里是绝对状态，
工程文件本身无法反推出「是谁发的」，详见第五节的不确定性说明。

三条硬证据：

1. **数值吻合**：卡住的 5 个 VSL 实例，`stretchFactor` 全部为 `0.2519228458`，
   反推 pitch bend = **63 / 16383**（几乎最低），偏差 **-1.98 半音 ≈ 你说的「低 2」**。
2. **时间吻合**：工程 12:42 保存，而 MIDI Deck 日志 **12:41:46 记录「推子目标沿用上次的选择：Pitch Bend」**——
   保存那一刻，推子正处于 Pitch Bend 模式。
3. **路由吻合**：MIDI Deck 输出到 `loopMIDI Port`，而工程里 `All MIDI Inputs` 出现 96 次，
   VSL 乐器轨是 OMNI 接收。

**注意**：同一 Preset 的两个实例可以一好一坏（1st Violins、Violas 都是如此），
说明这是**逐实例的运行时状态**，不是 Preset 本身的属性。

### 为什么是这几条

VSL 里 `stretchFactor` 是**被 pitch bend 自动驱动的**：

```
data.custom.paramControl.mappings.stretchFactor.source    = "pitchBend"
data.custom.paramControl.mappings.stretchFactor.rangeFrom = 0.25
data.custom.paramControl.mappings.stretchFactor.rangeTo   = 0.75
```

而乐器的弯音范围是：

```
data.parameters.pitchBendRange = 2.0   （±2 半音）
```

所以当 pitch bend 被压到最低时，音高偏移上限正好就是 **-2 半音**。

抵达路径：

```
MIDI Deck → loopMIDI Port → Nuendo "All MIDI Inputs"（OMNI）→ VSL 乐器轨
                              ↓
                    stretchFactor 被拉到 0.25 附近
                              ↓
                    Nuendo 保存工程 → 这个值被写进 .npr
                              ↓
                    下次打开工程，Nuendo 不会自动补发 PB=8192 → 永久偏低
```

## 三、MIDI Deck 确实会发 pitch bend（代码实证）

`bridge/server.py`：

```python
def send_pitch_bend(self, channel: int, value: int):
    """Send Pitch Bend. value 0-16383, center=8192."""
    v = max(0, min(16383, value))
    dw = ((v & 0x7F) << 16) | (((v >> 7) & 0x7F) << 8) | (0xE0 | (channel & 0x0F))
    self._winmm.midiOutShortMsg(self._hmo, wintypes.DWORD(dw))
```

推子目标**可以**设为 Pitch Bend（`cc = None` 即代表 PB）：

```python
log.info("推子目标沿用上次的选择：%s",
         "Pitch Bend" if remembered["cc"] is None else "CC%d" % remembered["cc"])
```

工程里的端口表也确认这条通路存在：

```
ID ....I|DirectMusic|loopMIDI Port
```

## 四、你自己的文档已经记录过同类缺陷

`docs/changelog/2026-09-19_mode-c-vibrato.md`：

> **症状**：停止摇晃后 DAW 的弯音停在某个值上，不回中心。

`docs/spec/mode-c-vibrato.md` §15.2：

> **弯音在 DAW 里是绝对状态**：手机一旦不说话（锁屏、WiFi 抖动、页面冻结/关闭、浏览器节流），
> 最后一条 PB 会一直留在 DAW 里。

同一份 spec §14 还留下过一条精准警告：

> 先确认**音源的弯音范围**：手机按 ±2 半音换算计数，乐器若设成 ±12 半音，同样的计数
> 会让实际音程变成 6 倍。调试页的「DAW 弯音范围（半音）」要填**乐器实际的范围**。

——「±2 半音」正是本次偏移量的来源。

### 现存代码缺口（建议修）

`update_target()` 在推子目标切换时**只清 CC 记录，不清 pitch bend**：

```python
def update_target(self, cc, channel, i=0):
    if i < len(self.mappings):
        if cc is not None: self.mappings[i]["target"]["cc"] = cc
        self.mappings[i]["target"]["channel"] = channel
        self._last_cc.clear()          # ← 只清了 CC，没有把 PB 归中
```

日志实测走了一遍这个路径：

```
12:41:46  推子目标沿用上次的选择：Pitch Bend    ← 切到 PB
12:47:54  推子目标沿用上次的选择：CC1           ← 切走，但没给通道补发 8192
```

**从 PB 切到 CC 时缺少一次归中**，残留的低值就留在 DAW 里了。
（`pb_all_centre` 只在「启动/停止」和「手机断开」时触发，覆盖不到这个路径。）

## 五、不确定性与边界

必须诚实说明的部分：

- **无法从工程文件反推是谁发的 PB**。pitch bend 是绝对状态，`.npr` 只记录「最终停在这个值」，
  不记录「哪台设备在何时推的」。
- 因此**不能 100% 确证**就是 MIDI Deck。同样连在 `loopMIDI Port` 上的其他软件
  （如 Pianoteq、其他 DAW）理论上也能发 PB。
- 但 MIDI Deck 是目前**唯一已知会主动、持续发送 pitch bend** 的程序，
  且时间戳（12:41:46）与工程保存（12:42）精确相邻。
- 日志中 `守护已关闭` 出现 0 次、`弯音清场（启动）` 65 次、`Starting on` 115 次，
  说明清场逻辑在多数启动中是生效的；缺口集中在**运行中切换目标**这条路径上。

## 六、建议动作

### 立即

1. **不要长期把推子目标设为 Pitch Bend**。当前 `fader.json` 是 `{"cc": 1, "channel": 0}`（CC1），是安全的。
2. 在 Nuendo 里对受影响的轨道**发一次 PB 归中**（或像你对 Vi 1 long 那样让 `stretchFactor` 回到 0.5）。
   剩余待处理的 4 个实例：`Vi 2 long` ×2、`1st Violins` 第 2 实例、`1st Violins Ostinato`、`Violas` 第 1 实例。

### 降低复发

3. 把这些弦乐轨的输入**限定到具体端口/通道**，不要走 `All MIDI Inputs`；
   或干脆把 `loopMIDI Port` 从 Nuendo 的 `All MIDI Inputs` 里排除。
4. 每次关掉 MIDI Deck 后，在 Nuendo 里确认一次弯音归中。

### 建议修改代码

5. 在 `update_target()` 里补一次归中：当推子目标**从 PB 切走**时，对原通道调用 `centre_pb()`。
6. 在手机端切模式 / 页面隐藏时（`centrePitchBendNow()` 已有）之外，
   补上「Bridge 侧主动切换目标」这条路径。

## 七、附：分析方法

VSL 插件状态在 `.npr` 里是 **zstd 压缩的 JSON**（魔数 `28 b5 2f fd`），
而非明文——这是先前纯文本扫描扫不到参数的原因。解压后即可逐项读取
`stretchFactor`、`pitchBendRange`、`enablePitchBendDetuning` 等全部参数。

提取出的状态快照保存在 `nuendo-diag/midideck-bend/`：

- `v1_long_151.json` / `v1_long_153.json`——Vi 1 long 改动前 / 改动后
- `v1_153.json`、`v2_153_a.json`、`v2_153_b.json`——153 版本下的各实例

依赖：`zstandard`（已装入沙箱环境）。
