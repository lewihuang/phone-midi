# 2026-09-28 X/Y Pad 加两个"快速预设"（弦乐表情 / X/Y Pad）

用户用法：「想到了可以直接用 XY 的方式同时输入 CC1 和 CC11，这样可以快速绘制弦乐的表情」，
并要求：「在 X/Y Pad 页面上加入一个选择开关，分别代表弦乐表情模式和 X/Y pad 模式，前者指向
CC1 和 CC11，后者指向 CC20 和 CC21。但是需要注意，虽然增加了选择开关，但**并不锁定 CC lane**，
只是给用户提供一个快速选择的方式」。

## 做了什么

`/xy.html` 上、CC 配置行正上方加一行 **快速预设**：

| 按钮 | 填的两个号 |
|---|---|
| **弦乐表情** | X = `CC1`（调制/颤音）、Y = `CC11`（表情） |
| **X/Y Pad** | X = `CC20`、Y = `CC21`（默认） |

点一下 = 把两个号填进输入框，然后走**既有那条路**（校验 → 立刻用新号发一次当前位置 → Bridge
落盘）。**没有新协议、Bridge 一个字都没改**：CC 号本来就是随每条消息带的（spec 决策 6）。

## 三个刻意的设计

1. **不锁定**：输入框不禁用、通道选择不动。预设只是"一键填号"，填完照样能手改——CC 号本来就
   常常要临时改（决策 6 的初衷）。
2. **高亮不撒谎**：按钮亮 = "当前这两个号正好是这套预设"。手改过任何一个号（例如 X=1、Y=12）
   → **两个都不亮**。不做"上次点过谁"的记忆 —— 那种记忆在手改之后就会与事实不符。
3. **仍然只有一组配置**：`xy.json` 里还是 `cc_x/cc_y/channel`，不做"多套命名配置档"。多套配置会
   让"现在到底在发哪两个号"变成隐状态，而 `xy.json` 也会失去唯一答案（spec §5 那条"不做预设"
   随之改成"部分开放"，决策 20 记了理由）。

## 实测（离线断言）

`tests/pages_smoke.mjs` 107 → **120** 项（新增 6 条，另 1 条旧的按新行为调整）：

- 两个按钮在页面标记里（桩 DOM 不解析静态文字，所以标签按标记断言）；
- 当前号是 30/31（不是任何一套预设）→ **两个都不亮**；
- 点「弦乐表情」→ `ccX=1`、`ccY=11`，并立刻发出 `{cc_x:1, cc_y:11}` 的那一条；
- **输入框没有被禁用**，且「弦乐表情」亮、「X/Y Pad」不亮；
- 手改成 `1/12` → 发出 `{cc_x:1, cc_y:12}`，两个按钮**都灭**；
- 点「X/Y Pad」→ 回到 `20/21` 并亮起。

## 已知代价（写在按钮的 `title` 里）

弦乐表情模式用 **CC1**，与**推子（Mode A/B）的 CC1 同号同通道**：别和推子同时跑（同一根线上会
互相扰乱）。要是以后真想两个一起跑，就得把 X/Y 挪到另一根线（`PhonePad`）——那要改 Bridge，属于
另一件事（用户已知道这个取舍）。
