# 2026-09-26 X/Y Pad 实现（二维控制面）

需求拷问定稿见 [spec/xy-pad.md](../spec/xy-pad.md)（19 条决策）；本页记录**实现**与实测。

一句话：手机屏幕变成一块**正方形二维控制面**，一个触点同时驱动两个 CC（绝对语义 + 松手保持），
用来控制粒子/颗粒合成器那个 X/Y Pad；Bridge 直接把它变成两条 `send_cc`，**不进映射引擎**。

---

## 改动

### Bridge（`bridge/server.py`）

| 内容 | 说明 |
|------|------|
| `kind:'xy'` 分支 | 一条消息 → **两条 `send_cc`**（X / Y 各一条）。在真正的消息分发 `_process()` 里接上，和面板触发并列 |
| 不走映射引擎 | 引擎是单轴的、还带 curve / dead-zone / smoothing；X/Y 两轴都是线性、无死区、无平滑。沿用 ADR 0004"离散事件绕开引擎"的先例 |
| 端口 | **与推子共用**（`self.midi`）。独立端口是面板才需要的——它的**音符**会被 `All MIDI Inputs` 里的音源轨（OMNI）吃掉；而 X/Y 的 CC 本来就是要喂乐器轨的 |
| 配置 | `%APPDATA%\phone-midi-bridge\xy.json`：`{cc_x, cc_y, channel}`，默认 **CC20 / CC21 / Ch1**（不撞推子的 CC1）。配置**随每条消息带来**，Bridge 以最近一次收到的为准，**变了才写盘**；非法值（越界、字符串、浮点、布尔）退回**已知的好值**，不会把配置弄脏 |
| 值的处理 | 四舍五入（不是截断）；越界钳到 0–127；`x`/`y` 不是数值就整条忽略 |
| PC 窗口 | `last_cc_output` 跟着显示 X 的值（与面板触发同一处理，X/Y 与推子不会同时用） |
| **顺带修掉的老毛病** | 推子的 `{type:'set_target'}` 以前**只改内存**，重启 Bridge 就回到 `default.json`（用户要求"记住上次的 MIDI out 与面板端口"时同类的毛病）。现在落盘 `fader.json`，并在两处建引擎的地方（GUI / CLI）用 `apply_remembered_fader_target()` 套回去 |

### 手机端（`web/xy.html` + `web/xy.js`）

- **正方形控制面**：`aspect-ratio: 1`，最大 420 px（390 宽的机器上约 358×358），四边都不顶屏幕边缘。
- **Position Marker + 十字准线 + 一行读数**（`X 64 · Y 96`）；不做网格、不做轨迹、不做轴反转开关。
- **未触碰 = "未定"**：虚线环停在中心、读数 `X — · Y —`、提示"点一下控制面开始"，**一个值都不发**
  （打开页面就发中心值会静默改掉插件里音色的位置）。
- **Landing**（每次新落点）走 **40 ms 补间**，沿途照发 —— 补间正是抹掉跳变的方式；
  **Drag**（按着移动）**不插帧、不平滑、不延迟**。
- **抬起什么都不发**（绝对 + 保持语义；也因此**不需要任何 watchdog**）。
- **第一根手指独占**，第二根落下不夺权。
- **回中**：走同一条补间到正中、结束时发出中心值。**冻结**：Marker 仍可拖、读数仍更新，但一个 CC 都不发；
  解冻时从"上次真的发出去的位置"补间到 Marker 并发出当前值 —— 正好是"先把云的位置摆好再生效"。
- **断连**：面变灰 + `pointer-events: none` + 读数「未连接」（宁可看起来不能按，也不做"悄悄不发"）。
- 两个 CC 号 + 通道在页面上可改，**改完立刻用新号发一次当前位置**，Bridge 会落盘记住。

## 实测

**Bridge 侧 21 项**（`tests/bridge_xy_check.py`，新增套件）：一条消息两条 CC、通道跟随、
不进引擎（推子的 CC1 一条没发）、走推子端口而面板端口一个字节不发、端点/四舍五入/钳制、
非数值忽略、默认值、落盘与读回、非法配置退回已知好值、不带配置的消息沿用、落盘前清洗、
布尔不是合法 CC、PC 窗口当前值、`kind:'xy'` 在真实分发里接上、推子目标落盘与重启沿用（含弯音只带通道）。

**手机端 19 项**（`pages_smoke.mjs`，含一条"三个模块都在首页"）：正方形标记、Marker/十字线、
未连接不可拖、**连上但没碰过时一条值都不发**、未触碰读数是"未定"、落点终点正确且**中间有过渡值**
（实测 x 序列 `68,76,83,89,95,103,110,116,124,127` —— 补间真的在插值）、标记跟到触点、
Drag 两次移动两条消息（无插帧）、抬起零消息、第二根手指不夺权、回中发出 64/64、
冻结期间零消息但读数更新、解冻发出一次、改 CC 号立刻生效、断连灰底且不发送。

**截图**：`%TEMP%\phoneshots_v9\xy.png` —— 白色面板 44.3%（正方形）、页面底 46.5%、配置输入框 7.5%，
Marker 是 `#818495` 的**虚线灰环**、**没有蓝色** = 正是"未触碰"状态（一条值都没发）。

全套 **323 项**通过（9 个套件；新增 `bridge_xy_check.py` 已登记进 `tests/run.ps1`）。

## 真机待确认（spec §7 的开放问题）

- 默认 **CC20 / CC21** 会不会和你的插件撞（撞了就改，改完会记住）。
- **40 ms 补间**够不够"听不出跳变"（这只是一个常量）。
- 冻结 / 回中 两个按钮是否够用。
- 是否需要在 DAW 侧写一份"粒子合成器 XY 面怎么学这两个 CC"的指南（Nuendo MIDI Remote 与插件
  MIDI Learn 两条路）。
