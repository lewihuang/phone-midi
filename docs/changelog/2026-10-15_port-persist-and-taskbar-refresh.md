# 2026-10-15（第二轮）三个用户报的问题：任务栏按钮没立刻出现 / 端口不被记住 / 冲突文案归因错误

用户报三件事：

1. **切到精简模式后任务栏没有提示**，但用 Alt+Tab 选中一次之后、即便焦点离开，提示又一直在了。
2. 手动把端口改成 **38765**，软件**没保存**，依然回到 8765（而 8765 会撞绿联 NAS）。
3. 端口冲突文案说"会与另一个 MIDI Deck 冲突"，但**大多数时候占用者并不是 MIDI Deck**，
   只需提示端口冲突、让用户改端口即可。

---

## 1. 任务栏按钮：改样式对了，但外壳不知道

上一轮（`2026-10-15_compact-taskbar-presence.md`）把 `WS_EX_TOOLWINDOW` 换成 `WS_EX_APPWINDOW`，
样式位确实对了。**但那只解决了一半**：任务栏（explorer 外壳）不会因为窗口改样式就重新枚举按钮。

实测（同一进程内，改样式前后各截一次任务栏按钮带，比较像素）：

| 变体 | 改样式后 exstyle | 任务栏像素变化 | 按钮立刻出现 |
|------|------------------|----------------|--------------|
| normal（普通窗口，参照） | — | 26472 | ✅ |
| **framechanged（上一轮实现）** | `0x00040008` | **0** | ❌ **复现用户现象** |
| hideshow（隐藏/显示一次） | `0x00040008` | 26472 | ✅ |
| ITaskbarList::AddTab | `0x00040008` | 26472 | ✅ |

**这就是用户看到的时序**：切到精简模式时按钮没出现（外壳还不知道有新窗口），等他按一次
Alt+Tab——那恰好是一次外壳事件，外壳顺带把按钮补上了，于是"之后一直都在"。

**修法**：改完样式、且是要**加**按钮时，再叫一次官方接口 `ITaskbarList::AddTab`
（`SetWindowPos(SWP_FRAMECHANGED)` 只让窗口自己重画，惊动不了外壳）。

- 优先走 COM（`_taskbar_list()` / `_taskbar_add_tab()`）：**不隐藏窗口**，所以不会把刻意隐藏
  或尚未映射的窗口显示出来（离线测试套件就是这种情形），真机上也没有闪烁。
- 拿不到 COM 时退回 `ShowWindow(SW_HIDE/SW_SHOW)`，并且**只在窗口本来就可见时**才做。

顺带明确一个事实修正：用户说"任务管理器里也找不到 MIDI Deck"——那本身不成立，**任务管理器里
本来就不该有它**（窗口程序只要不崩就一直在）。用户真正想看的是任务栏那条"正在运行"的指示，
所以修的正是这一条。

## 2. 端口不被记住

原实现里端口**从来没进过 prefs**：`_port_var` 硬编码 `value="8765"`，`_on_start()` 只存
`midi_out` / `pad_port`。所以每次打开都回到 8765。

**修法**：端口和窗口尺寸一样属于"用户改过就该记住"的东西，落进同一份 `window.json`。

| 位置 | 改动 |
|------|------|
| `DEFAULT_BRIDGE_PORT` / `PORT_MIN` / `PORT_MAX` | 新增常量（8765 / 1024 / 65535） |
| `load_window_prefs()` | 读回 `port`：**只认范围内的真整数**（bool 是 int 的子类，单独挡掉） |
| `_build_setup()` | 输入框初值 = 记住的端口（没有记录才用默认） |
| `_port_from_var()` | 新增：解析输入框；非法/越界/空 ⇒ 退回记住的值并记日志，绝不崩 |
| `_on_start()` | 存 `port`，并把钳正过的值回填输入框 |
| `_capture_window()` | 退出时也存一次（**改了端口但没点 START 就退出**也不丢） |

## 3. 端口冲突文案

原文案："端口 8765 已被占用：已经有一个「MIDI Deck」在运行，手机的连接进的是那一个。"
——**在猜占用者是谁**。实测本机 8765 是被**绿联 NAS 客户端**占着的，和 MIDI Deck 毫无关系。

**修法**：新增 `port_in_use_msg(port)` 统一文案，只说事实 + 建议，不提任何占用者名字：
> 端口 8765 已被占用，无法启动。请换一个端口再试（在上方 port 输入框里改，改完会被记住）。

四处调用点统一改用它：`bind_server_socket()` 的两处 raise、GUI 的 `_start_server()` 错误分支、
CLI 的 `_cli_mode()` 日志。

## 4. 验证

新增回归断言（`tests/bridge_ui_check.py`）：

- 端口占用文案**不含** `MIDI Deck` / `Bridge`，且含"已被占用"与"换一个端口"
- `port` 读回：合法值能读回；字符串 `"38765"`、`70000`、`80`、`True` 一律不认
- 设置页输入框填的是记住的端口（不是 8765）
- `_port_from_var()`：`abc` / `99999` / 空 ⇒ 退回记住值；`50000` ⇒ 原样采用
- 点 START 会把端口写进 prefs

全套通过：

| 测试 | 结果 |
|------|------|
| `bridge_ui_check.py` | **51/51**（原 39 + 新 12） |
| `bridge_protocol_check.py` | 21/21 |
| `bridge_boot_check.py` | 9/9 |
| `bridge_pad_check.py` | 74/74 |
| `bridge_port_check.py` | 12/12 |
| `bridge_xy_check.py` | 21/21 |
| `vibrato.test.mjs` | 64/64 |
| `pages_smoke.mjs` | 120/120 |
| `mode_b_latency.test.mjs` | 26/26 |

**端到端**：

- 用**真实 `server.py`** 从"零个 MIDI Deck 窗口"直接进入精简模式 → 任务栏像素变化 **26472**
  （与普通窗口参照值一致），即按钮**立刻**出现，不再需要 Alt+Tab。
- 端口：改 38765 → 重启 → 输入框仍是 38765 ✅；改成 41234 后**不点 START 直接退出** → 重启仍是 41234 ✅。
- 打包后的 `MIDI Deck.exe` 启动正常，主窗口 `ex=0x00000100`（正常应用窗口，占任务栏）。
