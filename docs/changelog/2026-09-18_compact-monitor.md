## 真正的问题：两个实例抢同一个端口

用户的现象是**手机显示"已连接"，PC 端 client 为 0**。我上一轮把它当成显示逻辑问题，
改错了地方。实际原因（本次实测证明）：

```
SO_REUSEADDR       第一个: OK
SO_REUSEADDR       第二个: 也成功了 <-- 这就是 bug
SO_EXCLUSIVEADDRUSE 第一个: OK
SO_EXCLUSIVEADDRUSE 第二个: 失败，正如预期
```

- 在 **Windows** 上，`SO_REUSEADDR` 不是 Unix 语义的"复用 TIME_WAIT"，而是**允许第二个进程绑定
  同一地址**，之后连接由其中一个（往往是最先那个）接收。
- 于是：上一个 Bridge 没关 → 新实例照样绑定成功并显示"运行中"+ 网址 → **手机连的是旧实例**
  → 新窗口的 `clients` 永远是 0。
- 更糟的是：绑定原本发生在**服务器线程内部**，失败时线程静默死掉，而 GUI 已经切到运行视图；
  exe 是 `console=False`，日志也没人看得到——**"看着在跑、其实没在跑"**。

### 修法

| 位置 | 改动 |
|------|------|
| `bind_server_socket()` | Windows 上用 **`SO_EXCLUSIVEADDRUSE`**（bind 之前设置）；端口若只是被 TIME_WAIT 占用则重试 10×0.2 s，若**确实有人在监听**则立刻失败 |
| `_port_in_use()` | 用一次 TCP connect 判断"是否真的有人在那儿监听"，用于区分"端口被占"与"TIME_WAIT" |
| GUI `_start_server()` | **在主线程先绑定**，成功后再起服务器线程、再切到运行视图；失败则调用 `_show_error()` 把原因显示在窗口里（"端口 8765 已被占用：已经有一个「手机推子」在运行，手机的连接进的是那一个"） |
| GUI `_show_error()` | 新增：exe 没有控制台，**只写日志等于没报错**；现在窗口直接显示"启动失败 + 原因" |
| CLI | 同样使用 `bind_server_socket()`，占用时打印中文原因并以退出码 1 结束 |

## 精简模式（按用户三条要求）

1. **只保留当前值 + 进度条**：`CC1 64` / `PB 8809` 大号字 + 一条进度条（CC 从左往右填，
   弯音以中线向两侧填）。没有状态卡片、没有按钮组，只有一个「展开」返回展开态。
2. **置顶**：精简态进入即 `-topmost True`（DAW 盖不住它）；返回展开态自动取消置顶。
3. **尺寸**：**不写死**。下限 `420×150`（按用户要求），可自由拉伸；
   尺寸只在本次运行内记住，**不落盘**。展开态保持原样 `480×420 / 下限 400×340`。

**没有做**（上一轮多做的那些）：窗口设置文件、DPI 感知、撞量程闪示、归中/暂停按钮、
emoji 图标、模式名推测、`clients` 之外的诊断数字。

进度条位置直接由已有数据算出，**协议与手机端零改动**：
`cc == "PB"` → `value / 16383`（居中），否则 → `value / 127`。

## 使用

1. 关掉所有正在运行的「手机推子」（**必须先关旧的**，否则新的会明确报错——这是设计如此）
2. 运行 `bridge/dist/手机推子.exe` → 选 MIDI 端口 → START
3. 点窗口里的「精简模式（置顶）」→ 得到一个只显示 CC 值与进度条、置顶的小窗，
   拖到屏幕角落并拉伸到合适大小

## 反馈修正（同日第三次）

连接成功后用户提出两点：

### 1. 精简窗：无标题栏、默认 420×150、可拉伸

- `overrideredirect(True)` **去掉标题栏**（返回展开态时恢复）
- 默认尺寸 **420×150**，下限也是 420×150
- 没有标题栏 ⇒ 原生边框也没了，所以**自己实现**：
  - 按住窗口任意位置**拖动**（`<Button-1>`/`<B1-Motion>` 记 `x_root/y_root` 差值）
  - 右下角 `◢` **拉伸把手**，拖动改尺寸并**钳制下限 420×150**
- 尺寸只在本次运行内记住，不落盘

### 2. 「第一次停止服务后再启动，提示端口 8765 已被占用」

**这是上一版我引入的新问题，原因有两层**：

1. `_on_stop()` 只是把关闭协程丢给服务器线程就**立刻返回** ✗：界面已经回到设置页，
   但旧监听还活着。手机页面在 2 秒一次地重连，于是端口探测发现"有人在监听" →
   新代码按设计报"已被占用" ✓ 与用户看到的现象完全一致。
2. 次要隐患：服务器停止时先关闭手机的连接，会让端口进入 **TIME_WAIT**；
   Windows 的**独占绑定拒绝**还带残留连接的端口（可能持续几分钟）。

**修法**：

| 位置 | 改动 |
|------|------|
| `_on_stop()` | 用 `future.result(timeout=5)` **等关闭真正完成**，再关闭并 join 服务器线程、清引用；之后才重建界面 |
| `bind_server_socket()` | 组合两种 Windows 行为：①**先探测是否真有人在监听**（一次 TCP connect），有人 → 直接报"已被占用"（防抢占，解决最初的 client=0 问题）；②没人监听但独占绑定失败 ⇒ 说明只是 TIME_WAIT ⇒ **回退用 SO_REUSEADDR 绑定**，让"停止后立刻启动"可用 |

回归测试（`bridge_boot_check.py` 8 项）：构造"服务器先关连接 → 服务器侧 TIME_WAIT"的真实状态，
断言**立刻重新绑定成功**；并打印本机纯独占绑定在该状态下的表现（版本差异，不作硬断言）。

> 实测记录：本机（Windows 10/11 当前版本）纯独占绑定在这种状态下**能**成功，
> 说明用户遇到的主要是第 1 层原因（`_on_stop` 不等）；回退逻辑作为跨版本保险保留。

### 其它

## 反馈修正（同日第四次）

### 1. 精简窗实际高度远大于 150

原因：**没有标题栏 ⇒ 窗口尺寸由内容的"请求尺寸"决定**，而 `tk.Canvas` 不给尺寸时默认请求
约 **378×265** ✗（我上一版只在展开态给了高度）。修法：精简态的 Canvas 用 `width=1, height=1`
+ `expand=True`（自己撑满但不提尺寸要求），并在控件建完后 `update_idletasks()` 再**重新应用**
一次请求尺寸作为最后一句话。现在实测请求尺寸就是 **420×150** ✓。

### 2. 点 START / STOP 窗口"未响应"好几秒

**先测，不猜**（临时脚本计时间）：

```
START 返回耗时: 692 ms          ← 每次点击都重建 TLS 上下文（含 cryptography 导入）
STOP  返回耗时: 5120 ms         ← 上一版加的 future.result(timeout=5) 超时
  端口立即可重绑: 是 (600 ms)
```

`runner.cleanup()` 在**手机还连着**的时候会一直排空连接（实测 >5 s）✗，而我把它放在界面线程里等 ✗。

修法：

| 位置 | 改动 |
|------|------|
| 启动/停止 | **全部移到工作线程**，界面线程只派发 + `after(50)` 轮询结果，`_set_busy()` 显示"正在启动…/正在停止…" |
| `_ssl_for()` | TLS 上下文**每次运行只建一次**（START 从 692 ms 降到几十毫秒） |
| `_on_stop` 的工作线程 | 顺序改为：`runner.shutdown()`（先关监听，端口立刻释放）→ 关 socket → `wait_for(runner.cleanup(), 1.0)` 尽力而为 → 取消任务 → 停 loop；不再无脑等 5 秒 |

实测（现在是断言，写进 `bridge_ui_check.py`）：

| 项 | 修复前 | 修复后 |
|----|--------|--------|
| START 派发（界面线程阻塞时间） | 692 ms | **1 ms**（后台就绪 698 ms，期间界面可响应） |
| STOP 派发 | 5120 ms | **1 ms** |
| STOP 完成 | — | **165 ms** |
| STOP 后端口立即可重绑 | — | **是** |

### 3. 测试当场抓到的第三个 bug

`_set_busy()` 会写 `_busy_lbl`，而该标签**只存在于设置页**：切到运行页后它已被销毁 ⇒
写它会抛 `TclError: invalid command name` ✗（真实使用中 **STOP 会直接炸**）。
修法：`_clear()` 一并清理 `_busy_lbl/_start_btn/_stop_btn/_tree/_port_var` 的引用，
`_set_busy()` 对每个写入都容错（`AttributeError`/`TclError` 都吞掉）；运行页用停止按钮
自己的文字（"停止中…"）+ 禁用状态来表示。

## 反馈修正（同日第五次）：精简窗尺寸比例不对

用户量到精简窗是 **630×510**，而请求的是 420×150。

**诊断（数字完全对上）**：630/510 = 1.235，而 **420/340 = 1.235** —— 说明窗口实际是
**420×340**：宽度是我请求的 420 ✓，高度被**展开态残留的 `minsize(400, 340)`** 顶住 ✗。
我上一版只在展开态设置 minsize，进精简态时没有改，于是请求的 150 被悄悄抬到 340。

**修法**：精简态 `minsize(420, 150)`（下限与默认一起走）；返回展开态时恢复 `minsize(400,340)`。

**实测（真窗口，未映射时不报真实尺寸，所以必须真的映射一次）**：
`tests/measure_window.py` → 展开 **480×420** ✓、精简 **420×150，比例 2.80:1** ✓。

### 关于 1.5 倍：本机系统缩放是 100%

查过三种口径，都指向 100%：

| 查询 | 结果 |
|------|------|
| `GetDpiForSystem()` | 96（100%） |
| 两台显示器的 `GetDpiForMonitor()` | 都是 96（100%） |
| 窗口自己的 `GetDpiForWindow()` | 96，且请求 420×150 实测就是 420×150 |

所以那 1.5 倍不来自本机显示配置；**比例问题（1.235:1 而非 2.80:1）确定已修**。
若修后仍看到 1.5 倍，说明是显示链路（远程桌面/驱动缩放/兼容性覆盖）在拉伸位图；
那时可选择让程序**感知 DPI**：窗口变成真正的物理 420×150、文字也更清晰，
但展开窗口也会从 720×630 物理缩到 480×420 物理（相对现在小 1.5 倍）——需要用户确认。

### 新增的手工核对工具

`tests/measure_window.py`：**真的把窗口映射出来**并打印实测尺寸与比例（会短暂弹窗几秒）。
未映射的窗口 `winfo_*` 不说真话，这类"窗口大小不对"的问题只能这样量。

## 反馈修正（同日第六次）：精简窗再压矮、进度条再减半

用户要求「进一步压缩高度，尤其是进度条的高度可以再次减半」。

原因很直接：进度条原来是 **`fill=BOTH, expand=True`** ——它吃掉窗口的剩余高度，
150 高的窗口里就有 **~78 px** 厚 ✗。

改动：

| 项 | 之前 | 现在 |
|----|------|------|
| 进度条 | 撑满剩余高度（约 78 px） | **固定 26 px 细条**（`fill=X`，不随窗口高度变）；多余高度留白 |
| 精简窗默认高度 | 150 | **108** |
| 精简窗下限 | 150 | **84**（比默认再矮一点，这样"还想更矮"是拖一下就够，不必改代码） |
| 值的字号 | Consolas 26 | Consolas 18（省高度，仍然醒目） |

实测（`tests/measure_window.py`，真窗口）：

```
展开态实测: 480x420
精简态实测: 420x108   比例 3.89:1（原 2.80:1）
进度条厚度: 26 px（原约 78 px）
```

宽度仍是 420。若想把进度条再调细/调粗，只需改 `COMPACT_BAR_H`（当前 26）一个数。

> 注：进度条改成固定厚度后，**拉伸窗口不会再改变条的粗细**（原来会一起变粗，
> 这也是它显得过厚的原因之一）。若希望"拉伸时条按比例变粗"，把 `fill=tk.X` 改回
> `fill=tk.BOTH, expand=True` 即可。

全套 **127 项**通过（64 DSP + 21 协议 + 8 启动 + 25 精简窗 + 9 页面）。

## 反馈修正（同日第八次）：标准窗回默认位置、精简窗记位置

用户澄清：**标准窗口每次打开回到默认位置即可；精简模式需要记住位置，可以与标准窗不同。**

| 窗口 | 位置 | 尺寸 |
|------|------|------|
| 标准（设置页 / 展开运行页） | **每次回到默认位置**（屏幕居中），不记忆 | 固定 480×420（原样） |
| 精简 | **记住上次的位置**（`compact_pos`），恢复前钳制进屏幕内 | 记住上次的尺寸（`compact`） |

`window.json` 只有 `compact` / `compact_pos` 两个键；上次我加的 `expanded` 键已去掉 ✗。

**记录时机**：关闭时（`_capture_window`，仍在拆服务器之前）；另外**离开精简态时**会把当时的
几何（尺寸+位置）暂存到内存 `_compact_geom`，所以"先进精简、再切回标准、然后关闭"也能记住 ✗✗
之前那种情况会丢。

实测（真窗口）：

```
标准窗口: (480, 420) 位置 (1040, 510)   ← 2560x1440 屏幕的正中，与计算值一致
精简窗手动移到 500x120 @(1234, 567)
关闭后落盘: {'compact': [500, 120], 'compact_pos': [1234, 567]}
```

顺带修掉一个**位置计算的隐患**：拖动窗口用的是 `winfo_x()`（真实位置），而未映射时它与
geometry 字符串不一致 → 第一次拖动会跳。现在统一从 geometry 字符串取当前原点
（映射后二者一致）。

全套 **135 项**通过（64 DSP + 21 协议 + 8 启动 + 33 精简窗 + 9 页面）。
