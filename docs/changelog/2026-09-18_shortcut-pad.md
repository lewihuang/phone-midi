# 2026-09-18 快捷键面板（Shortcut Pad）实现

## 背景

需求与 13 条决策见 [spec/shortcut-pad.md](../spec/shortcut-pad.md)，触发为什么走 MIDI Note 见
[ADR 0004](../adr/0004-midi-note-triggers.md)。本页记录**实现**：改了什么、测到什么。

一句话：手机/平板变成一块 **8 格（4×2）的宏命令按钮面板**，PC 端把这块面板镜像出来并可编辑，
改完即时同步到手机；按下时 Bridge 发一条 MIDI Note，Nuendo 侧用 MIDI Remote 把那条件映射到宏。

## 改动

### 手机端（新页面）

| 文件 | 内容 |
|------|------|
| `web/pad.html` | 独立页面：大标题 + 4×2 网格 + 底部页签；`100dvh` 单屏不滚动、禁缩放/长按菜单/选中 |
| `web/pad.js` | 渲染 Bridge 下发的布局；`pointerdown` 发 `{kind:'trigger',id,phase:'down'}`、`pointerup` 发 `up`；未连接时格子不可点；断连时先松开所有按住的键**再**断开；忽略不认识的服务器消息（为将来的状态回读留路）；申请 screen wake lock |
| `web/index.html` | 主页加入口「快捷键面板 · 宏命令按钮」 |

按下的判定用 `pointerdown` 而不是 `click`：`click` 在移动端有延迟，而这个功能的全部意义就是"按下即发生"。

### Bridge（`bridge/server.py`）

| 内容 | 说明 |
|------|------|
| `WinMidi.send_note(note, channel, velocity)` | 力度 > 0 发 Note On、= 0 发 Note Off；与 `send_cc` 同一个 `midiOutShortMsg` 位布局 |
| `trigger` 消息分支 | `{"kind":"trigger","id":N,"phase":"down"\|"up"}`，**不进映射引擎**（无范围、无曲线、无平滑），直接变成 Note 36+N / 通道 16 |
| 编号校验 | 越界或非整数编号只记日志，不发消息 |
| `pad_watchdog()` | 手机丢了"松开"（页面被关、WiFi 断、标签页被杀）时 1 秒内补 Note Off——与弯音的 dead-man 定时器同一类兜底；断开连接时也会清扫所有按住的触发 |
| 布局存储 | `%APPDATA%\phone-midi-bridge\pad.json`（与 `window.json` 同一约定；**不能**放 `config/`，那是 exe 的快照目录）。读取时清洗：坏 JSON / 缺格 / 超长文字 / 调色板外的颜色 / 超页数，一律退化或修正，绝不输出不可用的布局 |
| 布局下发 | 连上就发 `{"type":"pad_layout"}`；`broadcast_pad_layout()` 给所有客户端广播（沿用连接时已有的 `{"type":"config"}` 推送机制，没有新链路） |

### PC 端编辑器（Tk）

Bridge 展开态新增「快捷键面板…」按钮 → 独立 Toplevel：页签、页标题输入框、**与手机严格同构的 4×2 格子**、
选中格子的文字输入框 + 8 色固定调色板、每格右下角只读显示 `N36…`。

- 用独立 Toplevel 而不是在主窗里做模式：主窗的几何契约（标准窗固定 480×420 且不记忆位置、
  精简窗记忆尺寸与位置）**一点都没被碰**，这是那八轮真机反馈换来的底线。
- 文字/标题输入做 300 ms 防抖后落盘 + 广播；颜色点击立刻生效。
- 删页要点两次（两次点击确认，而不是可能被 DAW 挡住的模态弹窗）。

### 缓存版本与打包

- 所有页面 `?v=` 统一升到 **23**（含新页面 `pad.js?v=23`）。
- exe 重新打包（**17.87 MB**），归档内 `web/*` 29 个文件与源码**逐字节一致**。

### 测试抓到的两个真 bug

1. **`web/pad.js` 断连时丢掉"松开"**：`ws.onclose` 里先 `ws = null` 再 `releaseAll()`，而 `send()` 在
   没有打开的 socket 时直接返回，于是 up 事件发不出去（服务端 1 秒兜底与断连清扫能救，但手机端的行为是错的）。
   由 `pages_smoke.mjs` 新增的 pointer 事件驱动测试抓到，已修：先松开、再置空。
2. **`BridgeApp._pad_page` 属性与方法同名**：`self._pad_page = 0` 把 `_pad_page()` 方法遮住，
   打开编辑器即 `TypeError: 'int' object is not callable`。由 `bridge_pad_check.py` 的窗口测试抓到，
   方法改名为 `_pad_page_data()`。

## 真机发现的端口泄漏 → 面板改用独立 MIDI 端口（方案 C）

**现象**（用户真机）：Note 36 能正常触发宏 ✓，但 **37 起音源轨跟着弹音**。

**原因**：Bridge 的端口有两个身份——① MIDI Remote 设备的输入；② `All MIDI Inputs` 的一员，
而工程里的音源/乐器轨读 ②，且音源是 **OMNI**，所以**通道 16 拦不住**。Note 36 恰好落在音源键区外
（或作为鼓/键位切换音），37 起落进可弹范围。

**排除的方案 A**：把该端口从 `All MIDI Inputs` 摘掉是标准做法，但用户机器上推子的 CC1 正是靠这条名单
（取消后推子失效，已实测）✗。

**采纳的方案 C：面板用独立 MIDI 输出端口。**

| 改动 | 内容 |
|------|------|
| `WinMidi` 第二个句柄 | `SensorHandler(..., pad_midi=...)`：面板的 Note 走它，推子的 CC/弯音仍走原端口；未配置时退回共用（既有行为） |
| Bridge 设置页 | 新增 **「面板端口」下拉框**（默认「与推子相同」+ 所有输出端口），`_pad_selection()` 解析为 `None` 或端口名 |
| 运行页 | 新增一行状态：`面板端口: PhonePad（与推子分离）`（绿）／`面板端口: 与推子相同（音源轨可能跟着弹音）`（橙）／打开失败时明确写"打不开，暂用推子端口" |
| 命令行 | `--pad-name PhonePad`（打不开则告警并退回推子端口，不阻断启动） |
| 测试 | +7 项：独立端口时 Note **只**出现在面板端口、松开同样、`pad_midi_isolated` 标志、推子 CC 仍走原端口、设置页默认值是两个方向 + 解析逻辑 |

**Nuendo 侧要做的事**（写进指南）：loopMIDI 新建端口（如 `PhonePad`）→ Bridge 面板端口选它 →
给这个新端口**另建一个 MIDI Remote 设备**（推子那个设备别动）→ **不要**给新端口勾 `All MIDI Inputs`
→ 在新设备里重学各条 Note。**推子那条路完全不动。**

| 改动 | 内容 |
|------|------|
| **布局 4×2 → 2 列 × 4 行**（D15） | 4×2 铺满时按钮扁而宽，浪费手机竖向空间。契约是"手机与 PC 编辑器同构"，所以两端 + 测试一起改；格子数仍 8，`?v=` 升 24 |

## 真机验证：通过 ✅

用户真机确认：**手机上按一格 → Nuendo 执行宏，且音源不再被误触发**。

### 走通的那条路（照这个顺序做，任何一步颠倒都会失败）

1. **loopMIDI 建面板专用端口**（如 `PhonePad`），与推子端口分开。
2. **重启 Windows MIDI 服务**（管理员）：`Restart-Service midisrv`。
   - 这是本轮最难查的一环：`Windows MIDI 服务` 只在**启动时**把老式（WinMM/loopMIDI）端口包装成新式 MIDI 设备
     （注册表/端口文件里表现为 `MIDIU_KSA_…` 设备实例）。loopMIDI 的虚拟端口**不产生 PnP 到达事件**，
     所以服务不重启，新建端口永远不会出现在 `Windows MIDI` / WinRT 那套枚举里 —— 而 MIDI Remote 用的正是那套。
   - 判据（客观、不用猜）：`%APPDATA%\Steinberg\Nuendo 15_64\Port Setup.xml` 里，新端口是否多出
     `I|Windows MIDI|<端口名>` 一条。只有 `DirectMusic` 一条 = 还没被包装。
   - **重启 Nuendo 没用**（枚举的是服务已经准备好的列表）。
3. **重启 Nuendo**，在 MIDI Remote 管理器里把设备的输入端口选成新端口。
4. **Bridge**：推子端口照旧、**面板端口**选新端口 → START（运行页显示绿色的 `面板端口: …（与推子分离）`）。
5. 手机 `/pad.html` 按格子 → 宏执行 ✓。

### 踩过的坑（都已写进指南）

| 坑 | 表现 | 结论 |
|---|---|---|
| 端口同时是 `All MIDI Inputs` 成员 | 音源轨跟着弹音（OMNI，通道 16 也拦不住） | 必须分端口；**取消 All MIDI Inputs 会弄坏推子**（其 CC1 靠这条名单） |
| 新建端口只被 DirectMusic 枚举 | 往新端口发消息，DAW 完全无反应 | 重启 `midisrv`（见上） |
| `enableemulated` 开关 | **每个端口都多出一份【模拟】副本** | 只挪 `ignoreportfilter`；`enableemulated` 不要碰（这是助手在本轮踩的坑） |
| 先绑"运输状态值" | `Transport.Stop` 用 TriggerPad 绑不生效 | 绑**命令 / 宏**更可靠（真机验证过宏这条路） |
